Core Scientific Paradigm: Online Telemetry Stream vs. Static CSVs

Cloud native observability systems cannot rely on static tabular datasets because microservice distributions drift dynamically. GriffinOps uses sliding window streaming ingestion, normalizes metrics via Robust Median Absolute Deviation (MAD), and predicts failure trajectories using Temporal Convolutional Networks (TCN) with Granger Causality.

📡 1. Continuous Telemetry Ingestion

Rather than an offline dataset, data arrives continuously across 5 core golden signals for all microservices:

1 Latency (ms) & Traffic (RPS)
2 Error Rate (4xx/5xx ratios)
3 System Saturation (CPU % & RAM %)

Sources: SigNoz OTel Collector via OTLP gRPC/HTTP spans + live synthetic baseline injections.

📐 2. Rolling MAD Normalization

To compare heterogeneous metrics (ms vs % vs RPS) without bias, metrics are dynamically converted into Modified Z-scores:

Modified Robust Z-Score Formula
Zt = 0.6745 × [ xt − Median(XW) ] / [ MAD(XW) + ε ]

Where MAD = Median( | XW − Median(XW) | )
W = 30-step rolling window buffer

A score of |Z| ≥ 2.5σ marks an impending hazard zone.

🧠 3. PyTorch TCN Forecaster

Uses Temporal Convolutional Networks with Dilated Causal 1D Convolutions ($d = 2^0, 2^1, 2^2$):

  • Causal Convolutions: Strictly prevents future data leakage ($t$ depends only on $\le t$).
  • Exponential Receptive Field: Captures deep history without recurrent vanishing gradients.
  • Dual Output Heads:
    • Multi-step trajectory forecast $\hat{Z} \in \mathbb{R}^{B \times F \times 10}$
    • Outage probability $\sigma(Wh + b) \in [0, 1]$
🔍 4. Granger Causality Discovery

Detecting anomalies is not enough; GriffinOps proves which microservice originated the failure:

Vector Autoregression F-Test
Yt = ∑ αi Yt-i + ∑ βj Xt-j + εt

Tests Null Hypothesis: β1 = ... = βp = 0 (X does not cause Y).
Accepted if p-value < 0.05.

Combined with RCAEval PageRank to isolate root-cause pods.
